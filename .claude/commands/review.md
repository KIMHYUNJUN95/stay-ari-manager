# 코드 리뷰 워크플로우

당신은 Stay-Ari Manager 프로젝트의 코드 리뷰 전담 에이전트입니다.
**리뷰 대상**: $ARGUMENTS (파일명 또는 기능명)

## 리뷰 절차

대상 파일을 읽고 아래 체크리스트를 순서대로 검토하세요.

---

## 1. 보안 체크 (Critical)

- [ ] **멀티 테넌트 격리**: 모든 Firestore 쿼리에 `companyId` 필터 있는가
- [ ] **API 키 노출**: 하드코딩된 토큰/키/비밀번호 없는가
- [ ] **입력 검증**: 외부 입력(사용자 입력, API 응답)에 적절한 검증 있는가
- [ ] **인증 체크**: 민감한 기능에 `user` / `companyId` 존재 확인 있는가

---

## 2. 기능 정확성 체크

- [ ] **비동기 처리**: useEffect 의존성 배열 올바른가 (`companyId` 포함됐는가)
- [ ] **에러 처리**: API 호출, Firestore 쿼리에 try/catch 있는가
- [ ] **로딩 상태**: 비동기 작업 중 로딩 표시 있는가
- [ ] **빈 상태 처리**: 데이터 없을 때 UI가 깨지지 않는가

---

## 3. 아키텍처 적합성 체크

- [ ] **상태 관리**: 불필요한 전역 상태 사용 없는가 (UserContext만 전역 허용)
- [ ] **패턴 일관성**: 기존 컴포넌트 패턴과 동일한 구조인가
- [ ] **재사용**: 기존 컴포넌트/함수를 재사용했는가 (중복 구현 없는가)
- [ ] **파일 위치**: 올바른 폴더에 위치하는가 (components/, hooks/, constants/ 등)

---

## 4. 코드 품질 체크

- [ ] **과도한 복잡성**: 단순하게 해결 가능한 것을 복잡하게 구현하지 않았는가
- [ ] **불필요한 코드**: 사용되지 않는 import, 변수, 함수 없는가
- [ ] **console.log**: 디버그용 로그 제거됐는가
- [ ] **타입 안전성**: undefined/null 접근으로 crash 가능한 코드 없는가

---

## 5. UI/UX 체크

- [ ] **반응형**: 모바일(`max-width: 768px`) 레이아웃 처리됐는가
- [ ] **스타일 일관성**: 기존 색상 체계 (`#1E293B`, `#4F46E5`, `#F1F5F9`) 따르는가
- [ ] **Tailwind 사용 금지**: Tailwind 클래스 없는가
- [ ] **접근성**: 기본적인 접근성 (aria-label, 키보드 탐색) 고려됐는가

---

```

🔴 Critical (반드시 수정)
- [항목]: [문제 설명] → [권장 수정 방향]

🟡 Warning (수정 권장)
- [항목]: [문제 설명] → [권장 수정 방향]

🟢 Good (잘 된 부분)
- [칭찬할 부분]

총평: [1-2줄 전반적 평가]
```
